## Automatic enrollment and execution milestones — 2026-11-03

Published Aurora API `20261103-9` (web remains `20261103-4`) and Lykes FreightOps API/daemon `aurora-enrollment-20261103-v2`. Backups: `/opt/aurora-auth/backups/20261103-9` and `/srv/freightops/lykes/aurora-enrollment-20261103-v2/freightops.dump`. No historical plan assignments were cleared.

New Nova orders from PB_ID 1893 onward enroll automatically, alongside the original pilot and already-bound records. Header-only document orders create one summary freight line with the actual piece quantity, total weight, and cube; detailed descriptions stay in notes. Empty BOL fields remain empty. Changes to existing physical freight still require reconciliation. New FreightOps orders created after the deployment cutoff enroll when they have a numeric PRO, mapped terminal, complete parties and freight. Incomplete records remain eligible on later passes. The bounded rollout currently supports at most 500 captured orders and 500 manifests; it fails explicitly rather than silently dropping records beyond that limit.

The native creation path has a separate opt-in and performs PRO duplicate/reservation checks, one-time freight seeding, and receipt storage in one transaction. Additive `AURORA_SYNC_ORDER_KEY` and `AURORA_SYNC_LINE_TOMBSTONE` tables were installed only in Lykes Test. `NativeReadOnly=true` remains in force for existing freight rows. Existing FreightOps line GUIDs survive the first Nova roundtrip and unchanged rows retain them if an older Nova writer drops the optional OPL_SYNC_ID column value.

Exact feed acknowledgments now bind automatically enrolled orders to their committed Aurora workspace identity. New FreightOps planning manifests then enroll once all members are bound. Native manifest references are preserved when the Aurora binding is established. Driver names resolve only when exactly one synchronized driver matches; missing or ambiguous identities remain held.

The first Nova identity return may race a dispatcher assigning the new FreightOps order. FreightOps accepts that identity and supplemental native row metadata only if all physical freight fields still match; barcodes and assigned freight remain unchanged. Empty optional defaults are equivalent to absent optional values, while clearing nonempty informational fields remains rejected. Regression checks cover both successful late binding and rejected physical changes after assignment.

Shared manifest milestones are Planning, Dispatched, En Route and Complete. Raw FreightOps warehouse status remains supplemental metadata. Execution writes require an actual non-future event time, immutable membership/resources, an expected native revision, and the native state-machine prerequisites. Nova dispatch closes a **loaded** FreightOps manifest; departure requires it already closed; completion requires native unloading/returns complete. No scan, POD, individual order delivery, or skipped intermediate status is invented. Missing intermediate milestones and warehouse prerequisites remain held for review; arbitrary physical freight edits still depend on Steve's stable-ID preservation change. Individual delivery/POD mirroring and replay of missed intermediate execution milestones are not implemented by this release.
